Accessibility statement

AccessDesk should work for everyone who needs to request, approve or review access, including people who use a keyboard, a screen reader, a screen magnifier, voice control or high contrast settings.

What you can do

  • Use every feature with a keyboard alone. The first link on every page skips to the main content.
  • Zoom to 400%, or use a window 320 pixels wide, without content being cut off. Wide tables scroll inside their own box.
  • Use Windows high contrast (forced colours) mode and still see focus outlines and status labels.
  • Use the site with JavaScript turned off. It does not use any.
  • Fix form mistakes easily. Every problem is listed at the top of the page, linked to its field and announced to screen readers.
  • Take your time. Sessions last 24 hours, and nothing on a page times out sooner.

How it is tested

  • Every page, including error states, is scanned with axe-core against WCAG 2.0, 2.1 and 2.2 level A and AA rules on every change. The build fails if any rule is broken.
  • An automated keyboard-only test signs in, asks for access and approves it without a mouse.
  • Automated tests check that pages fit a 320 pixel wide screen and keep visible focus outlines in forced colours mode.

Known limitations

  • Automated tools find only some accessibility problems. AccessDesk has not yet been tested by disabled users or audited manually with screen readers.
  • Times are shown in UTC only.

Compliance status

AccessDesk aims to meet WCAG 2.2 level AA. It passes all automated checks, but until a full manual audit is done it should be treated as partially conformant.

Reporting problems

If something does not work for you, open an issue in the project's GitHub repository. Say which page you were on and what happened.
